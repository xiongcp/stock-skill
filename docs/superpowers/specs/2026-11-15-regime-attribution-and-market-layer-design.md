## 1. 背景与目标

### 1.1 问题

用户的观察：大盘好的时候分析就对，大盘不好就没法分析；形态也不只是 ABC，还有 ABCD、双底、诱多；个股应当参考大盘的形态和周期。希望从多个角度突破量化模型的随机性，做到真实可靠。

仓库里已有的证据与这个观察一致。主做多计划在开发区（2021–2026，样本内，三市场共 137,565 个独立事件）的结果，A 股按年份看：

| 年份 | 扣费单笔均值 | 相对同日随机基准的超额 [分块 95%] |
| --- | --- | --- |
| 2022 | −0.451% | −0.213% [−0.47, 0.06] |
| 2023 | −0.419% | −0.032% [−0.23, 0.17] |
| 2024 | +0.520% | +0.123% [−0.08, 0.32] |
| 2025 | +0.433% | −0.203% [−0.33, −0.08] |

数字取自主做多计划设计文档第 9.3 节。收益跟着大盘年份走，相对"同一天随机挑股票、挂同样形状的单子"的超额始终在 0 附近。反转层在开发区有超额，换到 2017–2020 留出集没有复现。此前的"70% 命中率"来自止盈止损的几何形状。

结论：多加几种形态不会让随机性变小。

### 1.2 "突破随机性"的定义

1. **把大盘的功劳和分析的功劳拆开。** 所有评估都对照同日随机基准，并按大盘状态分组报告。
2. **结构识别做全，且每个判断可证伪。** 并列给出互相竞争的结构假设，每个都有确认条件和失效条件。
3. **让大盘的形态和周期进入个股分析。** 现在只用了一个状态评分和 20 日相对强弱。
4. **未验证的能力只能让系统更保守，不能升级评级。** 要升级，必须先通过预注册的留出集验收（AGENTS.md 第 1.5 条）。

"真实可靠"在本项目里指：可复现、可证伪、分状态如实报告。它不等于保证盈利。

### 2.3 0A：计划收益的分状态拆解

口径与主做多计划开发区诊断完全相同：5 日限价成交层、episode 口径（同标的间隔 21 个日历日）、扣费、同日随机移植几何基准、超额按"信号 episode − 当日基准均值"配对、区间按信号日分块 bootstrap（2,000 次，种子 20261020）。

分组在看结果之前写定，共两类。

**事前分组**（信号日当时可知，可以用于决策）：

| 编号 | 分组变量 | 取值 |
| --- | --- | --- |
| E1 | 基准的 `regime`（`strategies.classify_market_regime`） | `TRENDING_BULL`、`TRENDING_BEAR`、`SQUEEZE_CONSOLIDATION`、`MEAN_REVERTING_RANGE`、`HIGH_VOLATILITY_CHAOS` |
| E2 | 基准的 `regime_score` | `<35`、`[35, 45)`、`[45, 55)`、`[55, 70)`、`≥70` |

基准状态按 (市场, 日) 计算一次，算法与 `analysis.analyze_bundle` 第 4 步相同：基准截至当日的K线取最近 420 根算指标，取最近 120 根调用 `classify_market_regime`，VIX 的取法与 `run_dev_region_v2.build_bundle` 相同。`<35` 一桶预期没有信号（大盘否决），出现多少如实报告。

**事后分组**（用到持有期内的信息，只用于归因，不能用于决策）：

| 编号 | 分组变量 | 取值 |
| --- | --- | --- |
| X1 | 持有期内基准收益的符号。基准收益从成交日前一个交易日的收盘算到出场日的收盘，完整盖住持有期 | 上涨、下跌（收益为 0 归入下跌） |
| X2 | 同上，按市场内三分位 | 低、中、高 |

另做一个线性分解：每个市场内，episode 净收益对持有期基准收益做一元回归，报告斜率、R² 与截距，三者的区间同样按信号日分块 bootstrap。截距的含义是"大盘不动时的平均单笔收益"。

每个格子报告：episode 数、信号日数、最大单日占比、净正率、扣费单笔均值与区间、同日随机基准均值、均值超额（P2b）与区间。episode 少于 100 或信号日少于 30 的格子标注"样本不足"，不做解读。

### 2.4 0B：正常波动范围的分状态覆盖率

主计划扫描时关闭了波动范围计算，所以 0B 需要单独跑一遍抽样：

- 抽样：开发区内全部合格的股票-日中，取 `sha256(标的 + 日期)` 的前 8 位十六进制数对 50 取模为 0 的那些（约 2%，约 12 万个股票-日，不依赖随机种子）。**实际执行时改为对 200 取模（约 0.5%，约 3 万个股票-日）**：覆盖与否在同一天内高度相关，精度主要取决于日期数；这一调整在看到任何覆盖率结果之前做出，分桶边界与样本不足门槛不变。
- 计算：对每个样本按 PIT 方式调用 `analyze_bundle(include_replay=False, include_forecast=True)`，记录第 5、10、15 步（数组下标 4、9、14）的 `conformal_50pct_band` 与 `conformal_80pct_band`。
- 实际值：同一 PIT 切片（as-of 当日的复权口径）中，信号日之后第 5、10、15 根已收盘K线的收盘价。未来K线不足的样本剔除并计数。
- 指标：实际收盘落在区间内的比例，按 E1、E2 分组，区间按日期分块 bootstrap。对照标称值 80% 与 50%。

样本数少于 300 或日期数少于 30 的格子标注"样本不足"。

## 3. 阶段 1：大盘结构与周期层

### 3.1 目标与边界

对基准指数跑一遍与个股相同的结构层，加上周线月线阶段和个股与大盘的对齐关系，作为描述性字段输出。

**本阶段不改变任何决策。** 规则分、评级、动作、否决条件与计划价位都不读取新字段。实现上，新结果放在内部报告的新键 `market_layer` 下，不并入传给评分与风控函数的 `benchmark_info`。

### 3.2 模块与接口

新模块 `kline-structure-chart/scripts/market_structure.py`，只做纯计算：

| 函数 | 输入 | 输出 |
| --- | --- | --- |
| `aggregate_bars_to_monthly(daily_bars)` | 已收盘日线 | 月线，只含已结束的自然月 |
| `classify_cycle_phase(daily_bars)` | 已收盘日线 | 第 3.3 节的阶段字典 |
| `summarize_benchmark_structure(bench_layer, bench_patterns)` | 基准的结构层结果与几何形态 | 第 3.4 节的结构摘要 |
| `compute_alignment(target_layer, bench_layer, target_bars, bench_bars)` | 两份结构层结果与已收盘日线 | 第 3.5 节的对齐字典 |
| `compute_market_layer(bundle, target_layer, horizon_bars)` | 行情包与标的结构层 | `{"structure", "cycle", "alignment"}` 或 `None` |

`analysis.analyze_bundle` 新增参数 `include_market_layer: bool = True`，在第 4 步之后调用 `compute_market_layer`，结果写入 `report["market_layer"]`（`contracts.AnalysisReport` 增加这个可选键）。`evaluation.run_plan_backtest` 调用时传 `False`：决策不依赖大盘层，回测不需要付出这部分计算。

基准结构层的调用方式：`compute_structure_layer(bench_bars, None, STRUCT_DAYS, price_decimals=…, horizon_bars=…, round_price=…)`，价格精度与取整按基准自己的市场和品种取值。基准K线已经是已收盘K线，且不晚于标的最后一根已收盘K线（`data_gateway.load_bundle` 保证）。

### 3.3 周期阶段

输入取最近 `HISTORY_BARS`（420）根已收盘日线，因此结果与取数长度无关。周线用既有的 `strategies.aggregate_bars_to_weekly`，只保留已完成的周，并丢弃第一个可能不完整的周。

记周线收盘为 `W`，`MA30 = SMA(W, 30)`：

- `slope_4w = MA30[-1] / MA30[-5] − 1`。`|slope_4w| ≤ 0.5%` 视为走平，阈值沿用 `structure.TREND_FLAT_PCT`。
- `pos_60w = (W[-1] − 近 60 周最低价) / (近 60 周最高价 − 近 60 周最低价)`。已完成周不足 60 个时用全部可得的周，实际用了多少周写入 `range_week_count`（键名避开价格白名单的 `range` 片段规则）。

未完成的当周不参与计算，所以阶段只在一周结束后更新。

| 阶段 | 条件 |
| --- | --- |
| `ADVANCE`（上升阶段） | `slope_4w > +0.5%` 且 `W[-1] > MA30[-1]` |
| `DECLINE`（下降阶段） | `slope_4w < −0.5%` 且 `W[-1] < MA30[-1]` |
| `TOPPING`（高位震荡） | 其余情况，且 `pos_60w ≥ 0.5` |
| `BASING`（低位震荡） | 其余情况，且 `pos_60w < 0.5` |

规则无状态：只看当前这一周的数值，不依赖历史上从哪一周算起。

附加输出：

- `phase_weeks`：按同一规则逐周回看，当前阶段已连续多少周。回看到预热不足的那一周为止，此时 `phase_weeks_capped = true`。
- 月线：已结束自然月的收盘相对 10 月均线的位置（`ABOVE` / `BELOW`）。

已完成周少于 35 个时，`phase` 及周线字段为 `null`，并给出 `reason`；已结束月少于 11 个时，月线字段为 `null`。

输出字段：`basis`（`BENCHMARK` 或 `SELF`）、`phase`、`phase_cn`、`phase_weeks`、`phase_weeks_capped`、`weekly_close`、`ma30w_price`、`slope_4w_pct`、`pos_60w_pct`、`range_week_count`、`high_60w_price`、`low_60w_price`、`monthly_vs_ma10`、`ma10m_price`、`reason`。

同一函数也用于标的自身，结果放在对齐字典里（第 3.5 节）。

### 3.4 大盘结构摘要

从基准的结构层结果中取出下列内容，字段形状与标的的同名字段相同：

| 字段 | 来源 | 对应的标的字段 |
| --- | --- | --- |
| `last_close` | 基准最后一根已收盘K线 | `structure.last_close` |
| `channel` | `layer["wedge"]`（去掉下划线开头的键） | `structure.channel` |
| `key_levels` | `layer["ladder"]` | `structure.key_levels` |
| `abc_scenario`、`wave_counts` | `layer["scenario"]`、`layer["wave_counts"]` | 同名 |
| `patterns` | 在基准结构窗口上调用 `detect_geometric_patterns`（双底、双顶、回归趋势） | `structure.patterns` 中的几何类 |
| `scenarios` | `layer["projections"]` 中的 `breakout_level`、`breakdown_level`、`scenarios`、`impulse_wave`，去掉只用于画图的键 | `scenarios` 中的同名字段 |

`result.json` 的体积预算（80 KB，`test_v6_result_validates_and_fits_budget`）不放宽。超出时裁剪大盘层：先去掉 `wave_counts` 中的备选计数，再去掉 `key_levels` 中非主要价位。

### 3.5 个股与大盘的对齐

按日期对齐标的与基准的已收盘K线，取最近 120 个共同交易日。

**联动程度**

- `beta_120`、`corr_120`：日对数收益的回归斜率与相关系数。共同交易日少于 60 个时为 `null`。

**相对强弱线**（`rs = 标的收盘 / 基准收盘`）

- `rs_trend_20`、`rs_trend_60`：`rs[-1] / rs[-1−n]` 不低于 1.02 为 `UP`，不高于 0.98 为 `DOWN`，其余为 `FLAT`。阈值与规则分里相对强弱的加减分阈值相同。
- `rs_at_60d_high`、`rs_at_60d_low`：`rs[-1]` 是否为最近 60 个值中的最大或最小值。

**拐点先后**

- 取基准最近一个已确认的波段低点，在标的的已确认低点中找时间最近、且相距不超过 10 根K线的一个（10 根沿用 `structure.MIN_RAIL_SPAN`）。
- `low_lead_lag_bars = 标的低点位置 − 基准低点位置`，位置按共同交易日的序号计算，负数表示标的先见低点；找不到时为 `null`。高点同理，输出 `high_lead_lag_bars`。

**新低新高对照**

- 取基准最近两个已确认低点 `L1`（较早）与 `L2`。标的在 `L1`、`L2` 各自前后 5 根K线窗口内的最低价记为 `m1`、`m2`。

| 基准 | 标的 | 标签 |
| --- | --- | --- |
| `L2 < L1`（创新低） | `m2 > m1` | `HIGHER_LOW_WHILE_INDEX_LOWER_LOW`（大盘新低、个股未新低） |
| `L2 < L1` | `m2 ≤ m1` | `LOWER_LOW_WITH_INDEX`（同步新低） |
| `L2 ≥ L1` | `m2 < m1` | `LOWER_LOW_WHILE_INDEX_HIGHER_LOW`（大盘未新低、个股新低） |
| `L2 ≥ L1` | `m2 ≥ m1` | `HIGHER_LOW_WITH_INDEX`（同步抬高） |

- `L2` 之后已收盘K线不足 5 根时，窗口右侧截到最后一根，并输出 `window_complete = false`：这时标签可能在随后几根K线内改变。
- 输出两个基准低点的日期和 `m2 / m1 − 1` 的百分比，不输出标的价位。高点对称处理。
- 结构窗口内基准的已确认低点不足两个时，低点对照为 `null`；高点同理。

本节与第 3.3 节新定的常量（30 周均线、4 周斜率、60 周区间、10 月均线、35 周与 11 个月的最低样本、前后 5 根的窗口、120 与 60 个共同交易日）在本文写定，实现时不调参。

**阶段对照**

- `target_phase` 与 `benchmark_phase`：两者各自按第 3.3 节的规则计算，并列给出，不再合成一个标签。

### 3.6 特殊情形

| 情形 | 处理 |
| --- | --- |
| 标的就是基准或指数（没有外部基准） | `structure` 与 `alignment` 为 `null`；`cycle` 按标的自身计算，并注明 `basis = "SELF"` |
| 缺少基准（本地文件输入） | 三个字段都为 `null`；既有的 `benchmark_missing = true` 与否决不变 |
| 基准历史不足 | 相应子字段为 `null` 并给出 `reason`，不估算、不补数 |
| 用户用 `--benchmark-symbol` 指定其他基准 | 按指定的基准计算，`index_symbol` 如实反映 |

### 3.7 因果性与不变性

- 只用已收盘K线。基准K线不晚于标的最后一根已收盘K线。
- 拐点只用已确认的（`confirmed = true`），其确认日不晚于截面日。
- `evaluation.run_causal_replay_audit` 新增可选参数 `bundle` 与审计项 `market_layer`：标的截到截面日，基准保留截面日之后的K线并把价格乘以 3；结果必须与基准也截到截面日时逐项相同（大盘层自己按标的最后一个已收盘日截断基准，不依赖上游对齐）。主 CLI 调用时传入 `bundle`；没有基准时该项写入 `modules_skipped`，不记为通过。
- 大盘层与 `--days` 无关：基准结构层的展示根数固定传 `STRUCT_DAYS`。由 `test_c06_pipeline_is_days_invariant` 覆盖。

## 5. 风险与预期

- **阶段 0 很可能显示任何大盘状态下都没有超额。** 这是可以接受的结果。那样的话，阶段 1~3 的价值在于分析的完整和可证伪，而不是找到优势。

- **A 股默认基准是沪深 300。** 用户习惯看上证指数时，可以用 `--benchmark-symbol` 指定，大盘层按指定的基准计算。
- **`result.json` 体积。** 大盘结构摘要与标的结构同形，体积可能接近预算，裁剪顺序见第 3.4 节。
