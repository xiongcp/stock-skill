## 1. 背景与目标

### 1.1 依据

阶段 0（开发区，样本内）给出三件事：

1. 主做多计划的单笔净收益跟着持有期大盘走：持有期大盘上涨时三个市场平均净收益为 +1.4% ~ +1.9%，大盘不涨时为 −1.7% ~ −2.0%。
2. 扣掉大盘后没有剩余：相对同日随机基准的超额在三个市场都在 0 附近或以下，27 个事前分组里没有一个样本充足的格子超额区间整体在 0 以上。
3. 正常波动范围在各大盘状态下的实际覆盖率都接近名义值（80% 区间整体为 80.7% ~ 82.5%，下跌趋势状态第 15 步低约 2 个百分点）。

所以产品里站得住的是"波动幅度"和"亏损限定"，站不住的是"方向"。现在的报告把结构与条件推演放在风控和波动范围之前，回测只和"同期买入持有"对比，读者容易把牛市里的盈利当成分析准。

### 1.2 目标

- A：让读者先看到波动范围和风控，再看结构；并用固定句子说明结构只是描述、计划盈亏主要取决于大盘。
- B：每份回测都把"这批成交的平均收益"和"同一批持有期里基准的平均收益"并排给出。

### 1.3 已确认的前提

| 编号 | 内容 |
| --- | --- |
| P1 | A 只调顺序和措辞，不动评级标签、规则分、否决条件与任何计划价位 |
| P2 | `result.json`、`chart_data.json`、`assets/analysis.schema.json` 不变 |
| P3 | 看板（HTML）与 PNG 不变 |
| P4 | 产品输出里不写阶段 0 的任何数字：那是样本内描述，不构成验收。新增的说明只用定性的固定句子 |
| P5 | `backtest.json` 只新增字段，不删除、不改名、不改已有字段的语义（6.x 规则） |

### 1.4 不在本文范围

- 评级标签或 `verdict` 的任何改动（需要 7.0）。
- 看板栏目顺序。
- 同日随机对照进入单只股票的回测：单标的运行没有股票池，做不了。
- 版本号：五处版本号保持 `6.0.0`，改动记在 `CHANGELOG.md` 的 `[Unreleased]`。

## 3. B：回测拆出大盘贡献

### 3.1 字段

`backtest.market_attribution`，对象始终存在。按"全部做多信号"（`all_long_signals`，单一合并持仓锁）的成交计算。

| 字段 | 含义 | 类型 |
| --- | --- | --- |
| `available` | 是否算出了归因 | 布尔 |
| `reason_cn` | `available = false` 时的原因，否则 `null` | 字符串或 `null` |
| `basis` | 固定为 `ALL_LONG_SIGNALS` | 字符串 |
| `benchmark_symbol` | 基准代码 | 字符串或 `null` |
| `trades` | 参与计算的成交笔数，等于 `all_long_signals.trades` | 整数 |
| `mean_net_return_pct` | 单笔净收益的平均值 | 数或 `null` |
| `mean_benchmark_hold_return_pct` | 各笔持有期内基准收益的平均值 | 数或 `null` |
| `mean_excess_vs_benchmark_pct` | 单笔净收益减去该笔持有期基准收益，再取平均 | 数或 `null` |
| `mean_excess_95ci_pct` | 上一项的 95% 区间，沿用 `_bootstrap_mean_ci`（少于 2 笔时为 `null`；该函数保留 2 位小数） | 两个数或 `null` |
| `benchmark_up` | 持有期基准收益大于 0 的那些成交：`trades`、`mean_net_return_pct` | 对象 |
| `benchmark_down_or_flat` | 其余成交（基准收益为 0 归入此组）：同上 | 对象 |
| `note_cn` | 第 3.3 节的固定说明 | 字符串 |

百分比保留 3 位小数。分组里没有成交时该组 `mean_net_return_pct` 为 `null`。

### 3.2 计算口径

- **持有期基准收益**：入场日之前最近一个基准收盘 → 出场日当天或之前最近一个基准收盘。与阶段 0 的事后变量 X1 相同；港股、美股个别日期基准没有K线时取前一个基准收盘，不报错。
- **不可用的情形**（`available = false`，数值字段全部为 `null`，`trades` 为 0）：没有基准K线（本地文件输入缺基准）；标的自身就是基准（代码等于基准代码或该市场的默认基准，此时流水线不加载基准）；`all_long_signals.trades` 为 0；任一笔成交的入场日之前没有基准收盘。`reason_cn` 分别写明。
- **只读已完成的回放结果**：在回放循环结束之后、汇总阶段计算，不进入任何决策日的输入。已有字段的值不变。

### 3.3 固定说明（`note_cn`）

> 超额是相对同一批持有期内的基准收益，不是相对随机选股；单只股票的回测没有股票池，无法判断选股本身有没有贡献。持有期大盘涨跌是事后才知道的，两组数字只用于拆解已发生的成交，不能用来择时。基准收益不含交易成本；个股用含分红的复权价，基准若是价格指数则不含分红，两者口径略有差异。

### 3.4 取舍

| 没做的事 | 原因 |
| --- | --- |
| 同日随机对照 | 需要当日整个股票池，单标的运行没有 |
| 净收益对基准收益做回归 | 单只股票通常只有几十笔成交，斜率与截距不稳定，给出来容易被当成结论 |
| 涨、不涨两组的占比 | 回复规则禁止频率与占比数字；只给笔数 |
| 按"确认做多""观察做多"分别归因 | 两者各有独立持仓锁，笔数更少；先只做合并口径 |

### 3.5 呈现与回复

- `report.md` 第 7 节在"同期买入持有收益"之后加一行：单笔平均净收益、同期基准平均收益、相对基准的超额及区间、两组的笔数与平均净收益；`available = false` 时写一行原因。
- `SKILL.md` 回复契约第 6 项加一句：有 `market_attribution` 时一并转述，并说明这是相对同期基准、不是相对随机选股；不得把"大盘上涨组"的平均收益说成大盘好时的预期收益。
- `references/output-fields.md` 的 `backtest.json` 字段表加上述字段；`references/interpretation-guide.md` 加一段读法。

## 5. 风险

- **读者习惯**：先看到波动范围再看结构，和常见的技术分析报告顺序相反。这是有意的；`CHANGELOG.md` 写明原因。
- **固定句子被当成免责套话略过**：它们放在各节第一行而不是文末，并写进回复契约。
- **少笔数下的超额被过度解读**：沿用 `sample_size_warning`，并在 `note_cn` 里说明它回答不了选股有没有贡献。
- **基准口径差异**：个股用含分红的复权价，沪深 300 与恒生指数是价格指数。差异方向对个股有利，量级小于单笔收益的波动；在 `note_cn` 中披露，不做调整。
