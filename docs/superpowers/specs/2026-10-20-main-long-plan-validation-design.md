# 主做多计划有效性检验：设计方案

- 状态：设计已确认（2026-10-20），待审阅文档后编写实施计划
- 日期：2026-10-20
- 检验对象：`kline-structure-chart`（5.3.0）`risk.compute_triple_barrier_plan` 输出的主做多计划
- 相关：[高置信反转层回测与验收口径调整方案](2026-10-20-backtest-acceptance-revision.md)（以下简称"反转层方案"），本方案沿用其方法论与守卫机制

## 1. 意图

线上技能对评级为 `LONG_CONFIRMED` 或 `WATCH_LONG_SETUP` 且未被风控否决的标的，给出入场区、止损、TP1、保本上移规则与建议股数，用户拿到的是一份可执行的做多计划。这份计划从未按反转层方案的口径（扣费期望、相对同日随机入场的超额、按信号日聚类的区间、一次性留出集）检验过。

本检验只回答一个问题：**现行主做多计划在各市场是否有超额**。结论直接决定各市场线上是保留计划，还是降级为观察位。

### 1.1 已确认的前提

| 编号 | 问题 | 决定 |
| --- | --- | --- |
| M1 | 检验目的 | 只判定现行规则，不调参。若要改进，另立新假设，只能用前向 H2 验收 |
| M2 | 验收对象 | `LONG_CONFIRMED` 与 `WATCH_LONG_SETUP` 合并为一个策略做硬判定；分档、分入场类型只报告 |
| M3 | 市场 | CN、US、HK 各自独立判定，三市场都用 PIT 前 1,500 只股票池；港股成交稀疏单列披露 |
| M4 | 未通过时的线上处理 | 该市场降级为观察位：不给做多评级与建议股数，只输出观察位并注明未通过验收（见第 6 节） |
| M5 | 推进方式 | 开发区诊断 → 冻结预注册 v3 → H1 一次性验收 → 按结果处理线上 |

### 1.2 现状

- 唯一一次检验是 v1 基线（`artifacts/long_backtest/runs/baseline_v1/metrics.json`，2021–2026，技能 v5.3.0 当时版本，约 141 万次决策）。5 日限价层扣费后净正率：CN 49.89% / 51.26% / 52.17%，HK 39.98% / 43.67% / 40.71%，US 52.60% / 51.08% / 47.17%（依次为原 dev / val / test）；`TP1 先于 SL` 为 CN 42.75%、HK 41.30%、US 44.33%。当时没有同日随机基准，也没有按信号日聚类的区间。
- 此后 PR #3（反量化分层门禁）、PR #4（过热提示被覆盖、港股止损误下移等）、PR #6（港股占位K线）都改动过主计划或其输入，现行规则未按 v2 口径检验过。
- 开发区 2021–2026 的主计划结果 v1 已经看过，只能算样本内。
- 留出集 H1（2017–2020）只为反转层运行过一次。已核对 `artifacts/long_backtest/h1_result.json`：不含任何主计划评级或收益统计，对本假设仍是干净的留出集，但需披露它已被另一假设使用。
- H2 前向跟踪的预注册只针对反转层，不含主计划。

## 3. 回测口径

### 3.1 信号

- 每个"股票-日"用截至当日的数据调用线上 `analyze_bundle`（与 `research/run_backtest.py` 现有做法相同：PIT 复权切片、基准截至当日、历史 VIX 取缓存当日值、不用实时快照元数据）。
- 评级为 `LONG_CONFIRMED` 或 `WATCH_LONG_SETUP` 即为一个主计划信号。大盘否决、盈亏比否决等风控已包含在评级中：被否决的标的拿不到这两档评级，不另行处理。
- 计划价位（`entry_zone`、`stop_loss_barrier`、`take_profit_1`、`breakeven_ratchet`）在信号日确定，之后不随成交价移动。
- 计划几何不满足 `stop < entry_low ≤ entry_high < tp1` 的信号不交易，单独计数（线上此时已因 `PLAN_GEOMETRY_INVALID` 否决，理论上不应出现）。

### 3.2 成交

- **主口径：5 日限价。** 以入场区上沿挂限价单，信号日后 5 个交易日内：开盘价不高于上沿则按开盘价成交，否则盘中最低价触及上沿则按上沿成交。成交价不高于止损时记为不成交（`GAP_BELOW_STOP`），开盘涨停等不可交易情况记为 `NOT_TRADABLE:<原因>`，均单独计数，不悄悄剔除。次日停牌（下根K线日期晚于下一个基准交易日）的股票-日与 v2 相同，不进入评估（`run_dev_region_v2._eligible_days`）。与 v1 和反转层研究一致。
- **报告口径：次日开盘落在入场区内才成交。** 这是技能自带回测 `LIVE_PLAN_REPLAY_V6` 的规则，只报告，不参与判定。

两种口径的差异本次只报告，不修改技能自带回测的规则；差异显著时另立事项。

### 3.3 出场

直接调用线上 `evaluation.label_triple_barrier_event`，不另写实现：

- 盘中触及止损或 TP1 离场；同根K线两者都触及时，按先触止损的保守规则；
- 盘中触及 +0.90R 且收盘 ≥ +0.30R 后，次日起止损上移至 +0.08R（参数取自计划的 `breakeven_ratchet`）；
- A 股 T+1、一字跌停无法卖出时顺延；
- 持满 15 根K线后按时间屏障离场；
- 扣除往返费用（按交易日生效的印花税等规则），另计 2bps 滑点。

### 3.4 去重与区间

- episode 口径：同一只股票相邻信号间隔不足 21 个日历日时只保留第一个。
- 判定用区间全部为按信号日期分块的 bootstrap 95%（2,000 次，种子写入预注册）；Wilson 区间只作参考。
- 每个格子同时给出 episode 数与不同信号日数；单个信号日贡献超过 10% 的 episode 时，加报剔除该日后的结果（敏感性分析，不参与判定）。

### 3.5 一致性测试

新增测试（`research/tests/test_main_plan.py`），在 `artifacts/long_backtest/cache/` 的真实行情缓存上抽样核对（研究管线只读这份缓存，与 v2 的同类测试一致；缓存缺失时跳过）：

1. 研究管线记录的评级、入场类型与计划价位，与线上 `compute_triple_barrier_plan` 的输出完全一致；
2. 研究侧的成交与出场标签，与以同一成交价调用线上 `label_triple_barrier_event` 的结果完全一致。

可参考 `research/tests/test_tensor_equivalence.py` 的写法。

## 4. 同日随机基准

主计划的价位随每只股票的结构（S1、R1、入场类型）变化，不像反转层那样是固定 ATR 几何。基准要回答："同一天随便挑一只股票、挂一个形状相同的单子，能否做得一样好？"

### 4.1 主基准：移植几何（P2b 使用）

1. 对每个信号，把入场区上下沿、止损、TP1 换算为相对信号日收盘价的 ATR14 倍数（ATR14 取计划实际使用的值，即 `risk.py` 中经 `max(0.5% × 收盘价, ATR14)` 下限处理后的值）。
2. 在同一信号日、同一 PIT 股票池中随机抽 10 只股票（抽样倍数 10，种子写入预注册；不排除信号股本身，与 v2 一致），把这组倍数套到各自的信号日收盘价与 ATR14 上，按交易所价位表取整。
3. 用同样的 5 日限价、出场规则、保本上移参数与费用撮合，同样做 21 天 episode 去重。

两边几何分布相同，超额只来自评级挑选标的的能力。

### 4.2 诊断基准：随机股票用自己的计划

随机股票使用流水线为它计算的计划价位（不论评级，`compute_triple_barrier_plan` 都输出价位）；几何自相矛盾的剔除并计数。它衡量"评级 + 结构价位"的合并价值，但非做多评级的计划几何本身不同，只报告不判定。开发区与 H1 本来就要对每个"股票-日"运行流水线，只需存下价位，几乎不增加计算量。

## 5. 验收指标与判定

### 5.1 硬门槛（每个市场单独判定，全部满足为通过）

| 编号 | 指标 | 门槛 |
| --- | --- | --- |
| P1 | 扣费后单笔净收益均值（5 日限价层，episode 口径） | > 0，且分块 bootstrap 95% 下限 > 0 |
| P2b | 单笔净收益均值 − 同日随机基准（移植几何）均值 | 分块 95% 下限 > 0 |
| P3 | 样本量 | episode ≥ 100，且不同信号日 ≥ 30 |

定义与反转层预注册 v2 逐字相同，只替换检验对象与基准。

### 5.2 只报告

- P2a：净正率 − 同日随机基准净正率（分块 95% 区间）；
- 净正率、`TP1 先于 SL` 比例（不设命中率目标）；
- 分组：`LONG_CONFIRMED` / `WATCH_LONG_SETUP`，`RIGHT_SIDE_BREAKOUT` / `LEFT_SIDE_PULLBACK`，按年份；
- 次日开盘成交口径的结果；
- 诊断基准（第 4.2 节）；
- 成交率与不成交原因分布（5 日未成交、跳空到止损下方、开盘涨停等不可交易、几何无效）；
- 费用翻倍敏感性。

### 5.3 判定规则

- P3 不满足（样本不足）同样判为未通过，没有"待定"状态。
- 三个市场是三个独立决定，不做多重检验校正。
- 开发区只评估 1 个配置（现行默认规则），H1 报告如实写明；同时披露反转层此前在开发区评估过 94 个配置（另一假设）。

## 6. 执行纪律

### 6.1 实施顺序

| 步骤 | 内容 | 验证 |
| --- | --- | --- |
| 1 | 研究管线：每个"股票-日"存下评级与计划价位；实现移植几何基准、诊断基准与打标签；一致性测试 | 一致性测试通过；冒烟结果可复现；AGENTS.md 第 3.3 节门禁通过 |
| 2 | 开发区诊断，只跑一次（默认规则），记入 `artifacts/long_backtest/trial_ledger.jsonl` | 本文档追加样本内结果 |
| 3 | 写入并提交 `research/preregistration/preregistration_v3_main_plan.json`，冻结 | 文件内 hash 与 HEAD 一致；守卫 `--check` 通过 |
| 4 | H1 一次性验收 | 结果写入 `artifacts/long_backtest/h1_main_plan_result.json`，按第 5 节逐项给出"通过 / 未通过 + 实际值 + 区间" |
| 5 | 按结果逐市场处理线上（第 7 节） | 门禁通过；浏览器检查 HTML |

### 6.2 开发区之后允许的改动

- **研究管线的缺陷可以修复**（不改变被检验的策略）。修复后重跑开发区并记入台账。
- **线上主计划代码**（`risk.py` 及其依赖的指标、形态、评分、数据模块）从步骤 2 起冻结，只允许修复**缺陷**：违反已写明的契约或铁律，例如计划几何自相矛盾、市场制度规则错误、数据真实性问题。"表现不好"不算缺陷。每项缺陷修复都要写入本文档、重跑开发区并报告修复前后差异。**禁止修改任何参数或阈值。**
- 开发区结果无论好坏都进入 H1：开发区结果不改变线上，只有 H1 是判定依据。

### 6.3 冻结与守卫

沿用反转层方案第 10 节的机制：

- **预注册内容**：代码 commit 与冻结文件的 sha256（技能全部脚本，研究侧的行情加载、PIT 切片、统计、主计划管线、守卫与预注册脚本）；H1 区间；股票池与行情缓存清单的 sha256；P1 / P2b / P3 的定义与门槛；基准抽样倍数、基准与 bootstrap 种子；登记前试验次数；披露事项。
- **数据 hash 在冻结时重新登记**，不直接引用 v2 的登记值。本机做 H2 联网实测时增量刷新过部分标的缓存，冻结前须核对各市场成分股在 H1 区间内的K线与 v2 冻结时逐根相同；不同之处如实写入预注册。
- **守卫脚本**：启动时逐项校验冻结文件与数据的 hash、工作区无未提交改动、预注册已提交，任一不符即拒绝运行；结果文件已存在即拒绝运行；启动时写锁文件，锁存在而结果缺失时须显式加 `--restart-after-crash`；`--check` 只做校验，不评估任何 H1 数据。结果单独写入 `h1_main_plan_result.json`，不触碰反转层的 `h1_result.json`。
- **H1 只运行一次。** 未通过时如实报告实际值、区间与可能原因，不得回到 H1 调参。

### 6.4 披露事项（写入预注册与 H1 报告）

1. H1 区间已被反转层验收使用过一次（未产生主计划统计）；
2. 开发区的主计划结果 v1 已看过，开发区结果属样本内；
3. 幸存者偏差：股票池只含当前上市标的，2017–2020 年退市股不在池中；
4. 历史 ST 状态不可得，只能按当前名称判断；
5. 港股成交稀疏：H1 港股池每期只有 51.6%~57.9% 的成分股期内 ≥95% 交易日有真实成交（反转层方案第 9.2 节）；
6. 交易日历只覆盖 2021 年起，不影响本回测（反转层方案第 9.3 节）。

## 7. 线上处理

### 7.1 某市场未通过

- 在 `risk.py` 新增 `MAIN_PLAN_PAUSED_MARKETS`，原因编码 `PAUSED_H1_MAIN_NOT_PASSED`。
- 暂停市场中，原本给出 `LONG_CONFIRMED` 或 `WATCH_LONG_SETUP` 的情况一律改为 `NEUTRAL_HOLD_WAIT`；原评级记入 `meta_labeling_decision.main_plan_paused_action`，供研究与 H2 读取。不新增评级枚举值。
- 不给建议股数（`recommended_shares = null` 并给出 `reason`）；入场区、止损、TP1 改称"观察位"，呈现方式与现有风控否决一致。Markdown 报告、HTML、PNG 顶部注明"主做多计划未通过留出集验收，已暂停"。
- `lint_response.py` 把暂停按风控否决处理，拦截回复中的买入建议与股数。
- 技能自带回测按原评级回放，并标注"已暂停计划的历史回放"（否则暂停后回测恒为空）。
- 同步修改 `SKILL.md` 的"对外表述与概率规则"、`references/output-fields.md`、`assets/analysis.schema.json`（新字段）、`CHANGELOG.md`，并补对应测试。

### 7.2 某市场通过

线上保持不变，不新增任何对外统计数字；结论记入本文档与 `CHANGELOG.md`。是否把主计划纳入 H2 前向跟踪另行决定，不在本方案范围内。

## 8. 风险与预期

- **结果大概率不理想。** v1 的净正率约 40%~52%，与随机入场相比可能没有超额；现行规则在其后加了过热降级等门禁，方向未知。H1 未通过是可接受的结果，重要的是结论可信。
- **计算量。** 需对 H1 与开发区每个"股票-日"运行完整流水线，规模与 v1 相当（开发区约 140 万次决策，H1 三市场上限约 295 万个"股票-日"，即基准交易日 756 / 593 / 615 天 × 1,500 只，实际受预热与上市日期约束）。步骤 2 实测耗时，长任务在后台运行。
- **2017–2020 与 2021 年后市场结构不同**（A 股注册制、港股流动性等）。H1 未通过不一定说明规则无效，但按 M4 仍降级；后续改进只能作为新假设用 H2 验收。
- **口径差异。** 技能自带回测的"次日开盘"口径与研究主口径不同，若两者结论相反，以研究主口径为判定依据，并另立事项统一。
