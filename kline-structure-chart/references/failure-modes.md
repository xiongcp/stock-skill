# 小模型执行本技能时最容易犯的错

本文件只用于理解错误类型。**不要在回答里引用本文件中的任何数字**，所有点位一律以本次脚本输出的 JSON 为准。

## 一、为什么不能用任何图像生成工具画图

扩散生图模型画K线和推演图时会出现以下事故：
1. **文字乱码**：英文 `Infographic` 被画成 `Infogcaph`，中文被画成「休投板流流量」「MAb60」之类的乱码。
2. **涨跌颜色画反**：把下跌阴线画成红色，而A股是红涨绿跌。
3. **双指数混轴**：把上证指数和创业板指画在同一根价格轴上，刻度顺序还会颠倒。
4. **伪造已发生K线**：把未来的K线画成实体红绿K线，让用户误以为已经收盘。

**正确做法**：始终运行主入口 `scripts/analyze_and_forecast.py`（同时产出 JSON、PNG 与 HTML）。PNG 由脚本画出真实的轨道、ABC 测算线与右侧三条推演折线，配色随市场（A股/港股红涨绿跌，美股绿涨红跌）。

## 二、写文字分析时的常见错误

回答的骨架以本次生成的 `*_report.md` 为准（见 `SKILL.md` 回复契约）。下表提到的 `legacy_summary.small_model_copy_blocks` 是 v4.1 兼容文案，只在需要补充结构细节时引用，不要与报告骨架重复拼接。

| 序号 | 常见错误 | 正确做法 |
| --- | --- | --- |
| 1 | 自己心算加减法或黄金分割点位 | 原样复制 `*_result.json` 里 `legacy_summary.small_model_copy_blocks` 的六个字段（0~5 号）。 |
| 2 | 漏写形态轨道、ABC 测算位或三条推演路径 | 完整粘贴 `3_wedge_and_levels`、`4_three_projections`、`5_structure_verdict`。 |
| 3 | 把不同指数的点位串在一起 | 上证只看上证的 JSON，创业板只看创业板的 JSON，每个指数单独成段。 |
| 4 | 把 ABC 的 A 浪低点当成窗口最低点 | 主图窗口最低点只看 `legacy_summary.window_low`，A 浪终点只看 `legacy_summary.scenario.a_end`，C 浪最远位置只看 `legacy_summary.scenario.c_progress`。 |
| 5 | 编造概率（如"上涨概率 60%"、"大概率突破"），或把 `rule_score`、状态分说成胜率 | 推演路径按「触发条件 → 目标价 → 失效条件」转述；历史频率只能引用 `rule_scenarios` 中的 `historical_frequency.display_cn`（必须带样本数 n 与 95% Wilson 区间，n < 30 注明低样本向基准收缩，且统一称"历史条件频率"，不叫胜率或上涨概率）。LLM 的"主观研判概率"必须严格按 `references/llm-judgment-protocol.md` 锚定基准概率、引用 `E1…En` 证据编号、写出 `*_judgment.json` 并通过 `scripts/validate_judgment.py` 校验后才能输出，且必须标注"主观研判，已记录待检验"。 |
| 6 | 把成交量写成"成交额 XX 万亿" | 只抄 `1_completed_summary` 里的"为5日均量的 X 倍、20日均量的 Y 倍"。 |
| 7 | 收盘后还写"盘中未收盘"，或沿用早盘的旧低点 | 每次回答都重新运行脚本，直接粘贴 `2_intraday_summary`。 |
| 8 | 按教科书改判形态（如"下降楔形，所以必然上涨"） | 形态和突破方向以 `5_structure_verdict` 为准。比如脚本写的是"收盘跌破下轨（向下突破）"，就不能说成"看涨楔形"。 |
| 9 | 盘中刚越过某个价位，就写成"已经跌破/突破" | 触发条件里带「盘中已跌破，待收盘确认」的，回复里也必须保留"待收盘确认"。 |
| 10 | 只贴模板，没有回答用户的具体问题 | 先用 1~2 句话、只用 JSON 里的数字直接回答，再给完整模板。 |
| 11 | 用户要看最近 300 天，就把形态说成"300日楔形"，或把年线、长周期黄金分割当成明天的突破位 | 形态、浪型和三条推演永远只基于近 120 日；大级别内容只抄 `0_long_cycle_context`，用来描述位置，不当作触发位或目标位。 |

## 三、消息面与资金面数据

两融余额、ETF 申赎、开户数、主力资金净流入/流出、海外 CPI 等数据，本脚本不计算。如果本轮对话没有用专门工具查到一手数据，在文字中一律注明「未复核」，不要从历史对话记忆里抄数字。

## 四、Flash / 轻量模型发出回复前 8 项必过自检表（Checklist）

在使用 Flash 模型生成最终回复前，逐条对照以下 8 项（也可直接运行 `scripts/lint_response.py` 自动检查）：

1. **否决是否置顶**：若 `debate_and_veto.risk_officer_veto == true`，回复第一段是否已明确写出「风控否决」及原因，且未给出任何做多买入建议？
2. **价格是否零改写**：回复中的所有价格是否与 `*_report.md` 完全一致（保留原本的 2 位或 3 位小数，未做四舍五入或心算加减）？
3. **规则分是否严守边界**：提到 `rule_score` 时是否明确称为「确定性规则加权分」，从未出现「规则分对应胜率/上涨概率/置信度」？
4. **历史条件频率是否完整带括号**：引用任何情景的频率时，是否完整保留了 `历史条件频率 X%（n = …，95% 区间 a%~b%）`（及 `n < 30` 时的低样本收缩说明）？
5. **保形区间是否注明无方向**：引用 `future_projection_15d` 时，是否说明「中枢 q50 = 最新收盘价，只描述波动幅度，不含方向预测」，且将 `scenario_conditional_fan` 明确标为「情景混合（非校准区间）」？
6. **板块特性是否提醒到位**：若标的为 `688`（科创板）或 `300/301`（创业板）等 20% 涨跌幅高弹性品种，是否提醒了「严格在 `entry_zone` 区间内挂单、避免短期乖离追高」？若激活「超跌反弹」且处于空头趋势，是否提醒了「待日线收阳站上触发位右侧确认」？
7. **L3 研判是否先过校验器**：若输出了主观研判概率，是否已通过 `scripts/validate_judgment.py`（建议使用 `--auto-init`）校验，并包含「主观研判」与「证伪条件」？
8. **结尾免责声明是否保留**：文末是否包含「以上为规则化技术分析，仅供研究参考，不构成投资建议」？
